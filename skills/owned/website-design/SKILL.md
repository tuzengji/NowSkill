# 网站设计

把用户的审美偏好落实到页面和交互中：核心内容清楚，文案直接，排版整齐，颜色舒服，细节有质感，动效自然，手机端同样完成设计。

这些偏好不限定网站的题材、技术栈、主色、字体或版式。用户当前的明确要求优先；维护已有网站时，保留已确认且不在本次修改范围内的品牌、内容、功能和特色效果。

## 根据任务选择工作方式

- 新建或整体改版：通读 [审美标准](references/aesthetic-standards.md)，结合内容确定布局、字体、配色、材质与动效。
- 局部调整：阅读标准中对应的条目，沿用现有设计体系，不顺带重做整个网站。
- 设计审阅：结合 [检查清单](references/review-checklist.md) 查看实际页面，指出具体问题和修改建议；用户仅要求审阅时，不直接改文件。

随包参考文件已经包含执行所需的偏好，不需要读取原始聊天记录或其他项目来使用本 Skill。

## 先判断页面服务于什么任务

| 用户在页面上的主要任务 | 布局与表现方向 |
| --- | --- |
| 查询、比较、浏览目录 | 有效信息集中，分类清楚，列表稳定，详情按需展开 |
| 编辑、评测、协作 | 工作区域占据主要空间，辅助面板可收起，常用操作就近安排 |
| 看品牌、作品、故事 | 有完整构图、阅读节奏和过渡，值得强调的内容得到充分呈现 |
| 玩游戏、回顾经历、参与体验 | 用贴题美术、场景和互动建立氛围，让操作融入内容 |

同一网站可以同时包含几种页面，分别安排密度与动效。不要把紧凑列表做成宣传落地页，也不要把沉浸式游戏做成普通后台。

## 设计与实现

### 了解现状，确定本次改动

先看用户提供的内容、参考效果和已有页面；有项目源码时，读取相关维护说明与样式，确认哪些部分已经定下来。以当前任务判断交付的是方案、页面实现还是审阅意见。

能从内容和既有设计判断的选择直接推进。只有缺失信息会改变主题、主要操作或改动范围时才询问；不把每次字体、间距或颜色调整都变成审批。

### 先整理内容与布局

让主要内容和操作占据合适的位置。删除重复副标题、解释小字和无用状态；必要说明保留在用户需要它的位置。收起挤压主体的辅助面板，统一同类内容的列宽、对齐和间距。

紧凑通过减少无效空白和重复信息实现，不能靠缩小所有文字、挤压按钮或删掉关键字段实现。展示页面的留白和分屏则应服务于阅读节奏。

### 再确定视觉和交互

选定一套相容的字体、颜色、控件和材质，让正文、菜单、弹窗与子页面连贯。偏爱柔和配色，同时保证文字和重点足够清楚；标题可以有个性，正文适合阅读。

涉及选择器或下拉菜单时，按[控件一致性标准](references/aesthetic-standards.md#10-控件与子页面属于同一套设计)检查真正展开后的菜单；给 `<select>` 的闭合态设置 CSS，不代表系统弹出菜单也已适配主题。

严格禁止装饰性色条：卡片、面板、弹窗的单侧强调线，以及标题旁的竖条，都不能使用；上、下、左、右四侧均适用。不得用伪元素、内阴影或渐变模拟，也不得在子任务、选中态或空状态中作为例外。需要区分或突出内容时，使用四边一致的完整边框、整体底色、柔和阴影和文字层级。

图标、图案和图片要符合题材，放进页面后检查比例、边缘和背景。用光影、纹理或玻璃等方法增加层次时，控制它们对文字和操作的影响。

为点击、选中、切换和展开安排自然反馈；承担氛围的页面可以有更明显的互动。按任务调整效果强度，不套用固定动画参数。用户指定参考效果时，观察它怎样运动和响应，不能只模仿静态外观。

### 在实际尺寸和状态中收尾

手机端重新安排列数、导航、弹窗、换行和装饰，桌面端合理利用宽度。检查加载、刷新、切页和高频操作，避免字体切换、布局跳动或装饰阻塞内容。

用 [检查清单](references/review-checklist.md) 核对本次涉及的页面和状态，修复发现的问题。检查范围随改动大小调整；无法进行实际浏览器验证时，如实说明验证范围，不把源码检查写成视觉验收。

## 交付

按用户要求交付可用的页面、修改后的代码或具体审阅结果。简要说明主要设计取舍、完成的改动和实际检查范围；不要用“高级”“惊艳”等形容词代替结果。

本 Skill 只约束设计取舍，不规定安装、仓库或托管方式。涉及提交和部署时，沿用当前任务与项目的既有约定。
