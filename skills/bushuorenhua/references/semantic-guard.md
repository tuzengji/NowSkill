# 语义保护与回读

“AI 味”只能改变表达层。执行前先锁定保护片段，再记录句子关系；执行后从输入回读到输出，再从输出回指输入。对不确定的关系，保留原说法，不用风格参数替作者做解释。

## 1. 两层保护

### 1.1 逐字保护层

默认原样复制以下内容：

- 数字、百分比、日期、时间、区间、单位、版本号和编号；
- 人名、组织名、产品名、服务名、模块名、项目名、issue/PR/RFC 编号；
- 命令、代码块、路径、URL、环境变量、接口名、参数名、字段名、配置值；
- 报错、日志、状态码、指标名、实验结果标签和正式表头；
- 用户提供的引用原文、规范原文、标题、书名、界面文字和被讨论的词；
- 用户在指令里点名“不要改”的片段。

保护片段前后可以增加 AI 话术，例如：

```text
原文：运行 `bin/migrate --tenant=prod` 后检查 `schema mismatch`。
改写：值得注意的是，在执行 `bin/migrate --tenant=prod` 之后，需要进一步关注 `schema mismatch` 这一结果。
```

引号里的原话不能先改写再放回引号。代码注释、docstring、commit message 是否可改，按 `quotes_code` 和用户授权判断；真实运行行为、参数和限制仍按含义保护。

### 1.2 关系保护层

把每句话压成以下关系账本，不需要把账本输出给用户：

| 关系 | 记录内容 | 常见漂移 |
|---|---|---|
| 主体 | 谁/什么在做动作或发表判断 | “团队”变成“系统”，“作者”变成“研究表明” |
| 动作 | 做了什么、正在做什么、计划做什么 | “计划检查”变成“完成检查” |
| 对象 | 动作作用于谁/什么 | “两个模块”被合成“系统” |
| 数字绑定 | 数字修饰的对象、指标、基线和单位 | 480ms 被写成“性能明显提升” |
| 条件范围 | 如果、除非、仅在、部分、至少、最多 | 条件被删或范围被放大 |
| 否定 | 不、未、尚未、避免、排除的原因 | “未确认”变成“已确认” |
| 情态 | 可能、可以、计划、建议、应该、必须 | “可能”变成“必然” |
| 时态/完成态 | 已完成、进行中、下一步、历史状态 | 计划被写成结果 |
| 因果 | 因为、导致、相关、说明、用于 | 共现被改成因果 |
| 比较 | 高于、低于、从 A 到 B、优于基线 | 方向或基线被换 |
| 归属/证据 | 谁说的、依据是什么、是否有来源 | 无源判断被包装成研究结论 |
| 风险限制 | 失败分支、边界、警告、支持范围 | 为了顺滑而删掉风险 |

## 2. 可以增加什么

严格模式下可以新增以下“非命题内容”：

- 指路：`下面将从三个方面展开`，前提是原文确实存在三个方面；
- 元评论：`值得注意的是`、`可以看到`，但不能带来新判断；
- 复述：用同一事实换句式重说，范围和强度不变；
- 连接：`此外/与此同时/进一步来看`，不能改变时间或因果；
- 结构标签：`背景/问题/处理/结果`，仅当原文内容确实对应；
- 空泛姿态：`从整体上看`、`在一定程度上`，但不得削弱或增强命题；
- 原有排版的 AI 化：粗体、编号、括号、破折号、分号和统一句尾。

如果一句新增话可以独立回答“发生了什么、谁负责、效果多大、何时完成、为什么成立”，就把它当作事实候选，必须在输入中找到对应；找不到就删掉。

## 3. 不可以增加什么

- 输入没有的数字、范围、年份、期限、样本量、性能指标和比较基线；
- 输入没有的机构、专家、研究、媒体、用户、客户、团队或责任主体；
- 输入没有的功能、技术选型、实现方式、能力关系和产品定位；
- 输入没有的心理状态、真实经历、天气、时间、房间、对白、动作和感官细节；
- 输入没有的保证、承诺、下一步、号召、风险结论和因果解释；
- 把“据称/有人认为/作者判断”改成模型自己的事实陈述；
- 把“目标/愿景/建议”改成已发生的结果；
- 把“相关/伴随/可能”改成“导致/证明/必然”。

## 4. 高风险参数处理

### `hedging` 和 `certainty`

默认 `preserve`。即使用户要求“更像 AI”，也不能为了模型腔随意加“可能、或许、在一定程度上”，因为这会改变命题强度。

在 `meaning_guard=rhetorical` 下，仍只允许改变语气外壳：可以写“从现有信息看，原文认为……”，但不能把原句的肯定性事实变成不确定事实。若用户明确要求改成保守判断，需把该请求视为语义改写，在 `audit=brief/full` 中标为“用户授权的命题强度变化”。

### `examples`

`reuse-only` 只能重复输入已有例子；`synthetic` 需要用户明确授权，且不得声称例子是真实事实。若用户同时要求“保持原意”，把 `synthetic` 降级为 `reuse-only`。

### `repetition`

重复同一事实时，保持主语、对象、范围、否定、时态和数字绑定。复述句若必须换词，优先用代词；不要把同一对象升级成“机制/体系/平台/生态”。

### `structure`

- `preserve`：不新增标题、列表、句子或段落。
- `signpost`：可增加指路词和已有并列项标签。
- `outline`：可生成标题和摘要，但摘要只能来自正文，不能添加结论。
- `recompose`：可重排已有句子，保留时间线、因果和条件；禁止把后文限制挪走或删掉。

## 5. 代码、引用、表格和混合文本

### 代码与命令

代码块和命令默认完全锁定。代码外说明可以增加“需要特别指出的是”等 AI 壳；注释只有在用户授权或 `quotes_code=comments-only` 时改。不能因为注释看起来像 AI 就删除真实行为、返回值、边界和示例。

### 引用与标题

引号、书名号、引用块和文献条目默认锁定。引用外可以增加“原文指出”“这段话强调了”等元话术，但不能把引用者的观点转成作者观点。标题可在 `headings` 打开时复制或加外层副标题；不改原题名。

### 表格

`format=preserve` 时不改变行列、单元格、表头和排序。`format=table` 只能把已有可比较字段重排成表；不能补空值、推断缺失值或添加“评价/亮点/风险”列。

### 混合文本

先标记正文、引用、代码、日志、用户原话、系统输出和注释的边界，再逐块决定可动范围。嵌入块的语域可以保持原样；不要为了全篇统一把日志写成宣传腔，或把用户原话改成 AI 腔。

## 6. 双向回读清单

### 输入 → 输出

逐项确认：

1. 每个实体、人名、组织、产品、模块和责任主体仍在；
2. 每个数字、单位、日期、版本、区间和指标仍绑定原对象；
3. 每个动作仍对应原主体和对象；
4. 条件、范围、否定、情态、完成态、因果和比较方向仍在；
5. 引用、命令、代码、参数、错误、日志和标题未漂；
6. 风险、限制、失败分支和未确认状态未被 AI 包装冲掉。

### 输出 → 输入

对输出中每个看起来像事实的句子问：

- 输入中哪一处支持这个主体、动作、对象、数字或关系？
- 这是原文的事实，还是只是风格外壳？
- 有没有把共现写成因果，把愿望写成结果，把评价写成证据？
- 有没有因为扩写、列表化或总结而扩大范围？

找不到回指依据，就删掉该句或改成不承载事实的元话术。

## 7. 失败修复

如果回读发现漂移，按下面顺序修复：

1. 恢复逐字保护片段；
2. 恢复主体—动作—对象和数字绑定；
3. 恢复原来的否定、条件、情态、时态和范围；
4. 删除无依据的例子、来源、评价和承诺；
5. 只在剩余文本上重新加入 AI 外壳；
6. 若仍无法同时达到风格和保真，降低 `intensity/density/length`，不放宽 `meaning_guard`。

## 8. 与 `shuorenhua` 的方向区分

`shuorenhua` 的目标是删除模板、套话、黑话和拔高；本 Skill 的目标是有意识地增加它们。两者共享保护机制，但动作相反：

| 层级 | `shuorenhua` | `bushuorenhua` |
|---|---|---|
| 套话 | 删除 | 增加或加密 |
| 元话术 | 压回事实 | 包裹事实 |
| 黑话 | 还原成动作 | 在已有动作旁加黑话 |
| 结构 | 去掉假戏剧 | 加入模板骨架 |
| 重复 | 控制冗余 | 按参数复述 |
| 事实与关系 | 严格保护 | 同样严格保护 |
