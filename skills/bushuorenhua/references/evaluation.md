# 评测与验收

这个 Skill 的成功标准不是“词越多越像 AI”，而是同时满足两件事：输出具有用户指定的 AI 信号，且原文命题没有漂移。任何保真硬失败都阻塞交付。

## 1. 硬门槛

以下项目必须为 0：

1. 数字、单位、日期、版本、命令、路径、字段、引用或错误信息被改坏；
2. 责任主体、观点归属或引用来源被替换；
3. 否定、条件、范围、时态、完成状态、比较方向或情态被改变；
4. 新增输入不存在的事实、来源、人物、机构、功能、能力、因果、例子、承诺、风险或后续行动；
5. `structure=preserve` 下新增/删除句子、段落、标题、列表或表格结构；
6. `quotes_code=lock` 下改动代码、命令、日志、引用和正式标识符；
7. 用户要求 `output=annotated` 时交付完整改写稿；
8. 用户要求 `meaning_guard=strict` 时执行 `certainty=harden/soften`、`examples=synthetic` 等命题变更。

## 2. 风格目标

风格不设一个适用于所有文档的固定词频，而按参数验收：

| 维度 | 通过条件 |
|---|---|
| 方向 | 输出明显比输入更模板化、更解释性或更黑话化，不是单纯校对。 |
| 强度 | `intensity=0/1/2/3/4/5` 的改动幅度递增，未越过保护边界。 |
| 密度 | `density=none` 基本无新信号；`high/saturated` 在多个段落稳定出现信号。 |
| profile | 词汇、句式、排版符合指定 profile，不把 tech 腔误写成 social 腔。 |
| 结构 | `preserve` 保持原结构；其他模式只使用输入已有信息。 |
| 长度 | 达到比例目标，或在无法安全填充时明确说明未满足。 |
| 可读性 | AI 味可以明显，但不因重复和黑话造成不可解析的指代混乱。 |

## 3. 最小回归集

每次修改 Skill 后至少用下面的输入做一次人工回读。每条都要同时检查风格和语义：

### A. 数字和指标

```text
本次优化把 p95 延迟从 480ms 降到 160ms。
```

应保留 `p95`、`480ms`、`160ms` 和“从—到”的方向；可以加“值得注意的是/这意味着”，不能改成“性能显著提升”。

### B. 情态和完成态

```text
这个调整可能改善加载速度，权限问题仍未解决。
```

应保留“可能”和“仍未解决”；不能写成“已经改善”和“权限问题已闭环”。

### C. 责任归属

```text
负责人建议下个版本先改搜索，团队尚未确认排期。
```

应保留“负责人建议”“团队尚未确认”；不能写成“团队决定”或“已排期”。

### D. 无源引用

```text
研究表明，这个方案可以降低成本，但原文没有给出来源。
```

可以把“研究表明”作为 AI 腔保留或重复，但不得补机构和数字；`audit=full` 应提示来源缺失。

### E. 代码和错误

```text
运行 `bin/migrate --tenant=prod` 后，如果日志出现 `schema mismatch`，检查 `DB_SCHEMA_VERSION`。
```

三个反引号片段和条件顺序必须逐字/按含义保留。

### F. 抽象判断

```text
该方法有助于提升协作效率，但没有说明具体机制。
```

可以增加“从整体协作链路来看”，不能补“减少沟通成本”“建立统一平台”等机制。

### G. 个人叙事

```text
我昨天在雨里等了两个小时，最后才拿到药。
```

这些细节来自输入，不能被当成“装饰性 AI 细节”删除；可以增加旁白和总结，但保留昨天、雨里、两个小时、药和先后关系。

### H. 混合文本

```markdown
系统返回 `504`。

> 用户说：“别把这句改掉。”
```

代码和引用锁定；只改引用外说明，且不把用户原话改成 AI 腔。

## 4. 参数边界测试

用同一段输入分别运行下列配置，比较输出差异：

```text
scene=docs, profile=generic, intensity=0, density=none, structure=preserve
scene=docs, profile=generic, intensity=3, density=medium, structure=signpost
scene=docs, profile=tech, intensity=5, density=saturated, structure=recompose
scene=public-writing, profile=social, intensity=4, density=high, length=expand:1.25
scene=academic, profile=academic, certainty=harden, meaning_guard=strict
```

预期：前三组 AI 痕迹逐步增加，第四组长度增加但不编事实，第五组拒绝把情态变强或在审计中报告未执行参数。

## 5. 评分卡

每项 0–2 分，先看硬门槛：

| 项目 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 保真 | 有明显命题漂移 | 有待确认的轻微歧义 | 全部可回指 |
| 保护片段 | 有改坏 | 个别格式需复核 | 逐字保留 |
| AI 方向 | 几乎没变化/变自然 | 有局部信号 | 方向清晰 |
| 参数遵从 | 多项未执行且未说明 | 大体遵从 | 全部遵从或明确降级 |
| 场景/语域 | 明显错配 | 局部混搭 | 一致 |
| 可读性 | 指代混乱 | 读起来偏满 | AI 味明显但可读 |

硬门槛失败时总分无效；通过硬门槛后，`intensity`、`density` 和 `profile` 相关项应至少达到 1 分，才算完成用户目标。

## 6. 输出前自问

- 这段是否真的更像模型，而不是更简洁、更自然或更像某个真人？
- 每个新增句子是风格外壳，还是偷偷回答了“发生了什么”？
- 所有数字、主体、条件、否定、情态、完成态和证据等级能否逐项找回？
- 如果删掉新增 AI 话术，原文的事实链是否完全恢复？
- 用户要求的是一份稿子、一个诊断，还是参数审计？交付形式是否匹配？
